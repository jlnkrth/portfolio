Playbook

Cursor, Codex, Claude Code: What I Use for Which

I don’t rank coding agents. I route jobs: Cursor for the screen, Claude Code for the team, Codex when I want a long run I can leave alone.

TL;DR
  • Cursor when the work is visual, local, or needs an editor I can steer mid-flight.
  • Claude Code when the job should match how Masse already works — plugins, skills, MCP, the team’s SOPs.
  • Codex when I want a second model, a long unattended run, or a check that Claude isn’t just agreeing with itself.

If you only steal one thing: pick the tool from the failure mode you can’t afford, not from the model leaderboard.

The problem

People ask me which coding agent is “best.” That question is broken. Best at what? Best for who? Best on Monday when you’re rewriting a landing page, or best on Thursday when fifty teammates need the same Asana skill to behave the same way?

I keep three tools open on purpose: Cursor, Claude Code, and Codex. Not because I enjoy collecting subscriptions. Because each one fails differently, and the job usually tells you which failure you can live with.

Symptom Cause
Pretty UI, broken spacing, “looks fine in the diff” You used a terminal agent for work that needed eyes on the screen
Great personal prompt, useless for the rest of the team You optimized for your IDE, not for a shared plugin / skill pack
Agent agrees with itself for three hours and ships a confident wrong fix One model, one session, no second opinion
You babysit a long refactor that should have been a background job You picked the interactive editor when you needed an unattended run

Most “the model is dumb” complaints are actually “I picked the wrong surface for the job.”

The system

I route by surface, not by brand loyalty. The question isn’t which company I like this month. It’s where the work wants to live: in an editor I can poke, in the team’s Claude Code install, or in a long job I walk away from.

Cursor [ screen + steer ]
Claude Code [ team + SOPs ]
Codex [ long run + second opinion ]
Leaderboard screenshots never the router

Three slots. If a fourth tool wants in, it has to steal a slot by winning a real job, not a demo.

Cursor — when the screen is the product

Cursor is where I go when I need to see the thing. Portfolio pages. Component spacing. A form that looks correct in HTML and wrong in the browser. Anything where “the tests passed” is not the same as “a human will trust this.”

It’s also where I stay when I want to steer mid-flight: select a block, nudge the agent, re-run, keep the editor as the cockpit. Cloud Agents fit here too — async PRs against a real repo when I’m away from the keyboard but still want Cursor’s project context, not a random chat window.

If the job is “make this page feel like my site,” I open Cursor. If I try to do that from a pure terminal agent, I spend the savings on screenshot ping-pong.

Claude Code — when the team has to match

Claude Code is the Masse default for a boring reason: we already packaged how we work into a plugin. Commands, skills, MCP servers, hooks. One install, fifty people, same behavior. That’s not a model preference. That’s distribution.

So when the job is an agency workflow — brief a client page, pull Search Console, write findings back to Asana, follow the wiki SOP — I start in Claude Code. Not because Anthropic won a vibe check. Because the Workbench already knows our judgment, and rewriting that judgment inside Cursor for one person is how config drift starts.

Personal coding can live anywhere. Shared practice needs a package the whole team updates through git.

Codex — when I want distance

Codex is what I reach for when I want a long job I can leave alone, or when Claude Code just gave me an answer that felt a little too smooth. Same prompt, different model family, different failure shape. If both land in the same place, I trust it more. If they diverge, I’ve found the part that needs a human.

I also use it when the work is mostly mechanical and long: migrate a pile of files, grind through a checklist, keep going while I’m in a meeting. Interactive editing is the wrong tax for that. An unattended run with a clear done condition is cheaper.

One caveat I keep writing on sticky notes: both Codex and Claude Code will politely route you into their own cloud when you ask for boring infrastructure. Ask for an Asana-triggered worker and watch them recommend themselves. That’s capture, not advice. Route around it.

Rules

The routing table fits on a card. If I can’t decide in under ten seconds, I’m overthinking and should just pick Cursor and start. 

ROUTING

1. Is the output judged by eyes / layout / brand?
   -> Cursor (editor + preview + Cloud Agents).

2. Does the team need the same SOP, skills, MCP?
   -> Claude Code (Workbench plugin).

3. Is it a long unattended job or a second opinion?
   -> Codex.

4. If two tools claim the same job, pick the one
   whose failure mode you can see fastest.

NEVER:
- Pick from a leaderboard screenshot.
- Let the agent pick its own cloud as "infrastructure."
- Duplicate team SOPs into a personal IDE setup.

Copy this into a note next to your dock. The point is speed, not purity.

A week in practice

Here’s what the router looks like when it’s working, instead of when I’m arguing about models on the internet.

Portfolio / UI polish Cursor
Client audit via Workbench Claude Code
Overnight file migration Codex
Same bug, two answers disagree Claude + Codex
Async PR while I’m offline Cursor Cloud

The labels are boring on purpose. Boring means you can teach it.

  1. Name the job in one sentence, including how you’ll know it’s done.
  2. Run the routing card. Don’t negotiate with yourself.
  3. If the first tool stalls twice on the same mistake, switch tools before you rewrite the prompt again.
  4. Write one line in findings.md if the wrong tool taught you something.

What changed in practice

I stopped having a favorite. That sounds small. It saved me from the expensive habit of forcing every job through whichever agent I was emotionally loyal to that month.

UI work got faster because I stopped asking a terminal agent to invent taste. Team work got more consistent because Claude Code stayed the package everyone installs, not my personal Cursor profile with secret sauce. Long jobs stopped eating my afternoon because Codex (or a Cloud Agent) could grind while I did something else.

And when two agents disagree, I finally have a useful signal instead of vibes. Disagreement is the bug report. Agreement across model families is the closest thing I get to confidence without a test suite.

If you only change one habit: write your own three-line router, tape it next to the dock, and refuse to open a fourth tool until it beats one of the three on a real ticket. The model race will keep moving. Your failure modes won’t.
