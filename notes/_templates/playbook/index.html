Playbook

One Place for Every Decision

A decision log so simple the team actually uses it.

TL;DR
  • Every decision lives in one file: decisions.md, newest first.
  • Write it down the moment someone says “okay, let's do that.”
  • Chat is for deciding. It is never the record of what was decided.

If someone only reads one block, this should still be enough to act.

The problem

Teams don't forget decisions. They lose them. The call was made in a thread, the thread scrolled away, and three weeks later two people are having the same argument with the same points and a different outcome. The cost isn't the ten minutes of rehashing — it's that nobody trusts a decision to stay decided, so nothing feels settled.

Symptom Cause
Same debate every few weeks Decision lived in a Slack thread nobody can find
“Wait, when did we agree to that?” Verbal decision, no written record at all
New teammates re-open settled questions No single place to read what was decided and why

Lead with observable symptoms, then tie each one to a concrete cause.

The system

One file per project, checked into the repo next to the code it governs. Not a wiki, not a Notion page, not a tool — a text file that shows up in every code review and every checkout.

decisions.mdthe log decisions/0007-drop-dark-mode.mdlong form
Slack, meetings, DMsnever the record

One canonical file lowers friction more than any process doc.

Most decisions fit in one line of the log. A decision only gets its own numbered file when the reasoning matters more than the outcome — the kind of call someone will want to challenge later.

Setup

Seed the file with the decisions you can still remember. Ten minutes, once.

echo '# Decisions' > decisions.md
Run once at the project root. That is the whole install.

Bootstrap should be one command, not a setup project.

Rules

The system works because the rules are few enough to remember without looking them up. 

WHEN A DECISION HAPPENS:
1. Write one line: date, decision, who called it.
2. If the reasoning is contested, add a numbered file and link it.
3. Post the line back into the thread where it was decided.
4. To reverse a decision, add a new line. Never edit old ones.

Rules should be copyable, testable, and short enough to memorize.

One rule is absolute: if it isn't in the log, it wasn't decided. Anyone may reopen an unlogged decision without apology.

What changed in practice

Arguments got shorter, because “check the log” ends most of them. Reversals got cleaner, because reversing a decision now means writing a new line next to the old one — you see what you're undoing. And new teammates stopped guessing: the log reads like a history of the project's judgment, which is the fastest way to absorb a team's taste.

The trick is not the file. It's the rule that chat never counts. Once people trust that everything binding lives in one place, they stop hoarding context in their heads — and the log starts writing itself.
