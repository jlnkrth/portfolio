/ html-host

A self-hosted publisher for sanitized, self-contained HTML page packages. Sign in, upload one HTML file or a folder of static assets, choose a slug, and share the URL. Optional viewer passwords per page.

git clone https://github.com/jlnkrth/html-host.git
GitHub Deploy docs

Features

  • Multi-file HTML packages (HTML entry plus local CSS, images, fonts, media)
  • HTML / CSS / SVG sanitization on upload — scripts and active content removed
  • Upload preview and recent-upload list on the admin origin
  • Optional password protection per page
  • Injected page toolbar (copy link, download HTML, print)
  • Admin dashboard with delete and activity timeline
  • Salted scrypt hashes, signed sessions, CSRF, rate limits, host-only cookies
  • Atomic filesystem storage — no database
  • Hardened Docker Compose deploy with automatic HTTPS via Caddy

Trust model

Built for a trusted administrator or small trusted team. Uploads are rewritten: scripts, event handlers, remote stylesheets, and other active content are stripped. Sanitization is not a substitute for access control — only give the upload password to people you trust.

Admin and content must use different hosts (ideally different registrable domains), so administrator sessions are not shared with the content host.

Requirements

  • Two DNS records pointing to the server
  • Docker Engine with Docker Compose
  • Ports 80 and 443 reachable from the internet

Local development without Docker needs Node.js 24+.

Production deploy

git clone https://github.com/jlnkrth/html-host.git
cd html-host
npm ci
cp .env.example .env
printf '%s' 'choose-a-long-administrator-password' | npm run --silent hash-password
openssl rand -hex 32

Put the generated hash and secret in .env, set ADMIN_HOST and CONTENT_HOST, and keep the hash single-quoted (it contains dollar signs). Then: 

docker compose --env-file .env --file deploy/compose.yml up -d --build

Caddy obtains and renews certificates after both DNS records resolve. Only Caddy binds host ports — the app container stays private.

Local development

.localhost names resolve to loopback in modern browsers. After npm ci and generating a password hash + session secret: 

ADMIN_ORIGIN=http://admin.localhost:3000 \
CONTENT_ORIGIN=http://content.localhost:3000 \
ADMIN_PASSWORD_HASH='scrypt$replace$replace' \
SESSION_SECRET='replace-with-the-generated-secret' \
STORAGE_DIR=./data \
npm run dev

Open http://admin.localhost:3000. Published pages appear at http://content.localhost:3000/<slug>/.
